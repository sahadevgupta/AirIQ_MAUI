1. ViewModels

Missing concurrency guard on LoadMoreAsync

HighAsync
Files
ViewModels/AccountLedgerRecordPageViewModel.cs:56-74, RefundsRecordPageViewModel.cs:56-74, SalesRecordPageViewModel.cs:58-76, TempCreditPageViewModel.cs:60-83
Why
No AllowConcurrentExecutions=false or busy guard. CollectionView.RemainingItemsThreshold can fire more than once before the first page finishes loading, or a user double-taps — concurrent calls read the same page value, issue duplicate API requests, and each independently increments the cursor.
Impact
Duplicate rows in the list, corrupted pagination cursor, wasted API calls.
Triggers
Fast scrolling near list bottom, or double-tap on a "load more" affordance.
Fix
[RelayCommand(AllowConcurrentExecutions = false)] or an IsLoadingMore flag as CanExecute.
Safe / minimal

2. XAML / UI

Static MAUI handler-mapper mutated from instance constructors

CriticalRendering / Handler-mapping
Files
Controls/BorderlessEntry.cs:9-26, Controls/SearchView.xaml.cs:94-117
Why
Both constructors call Handler.Mapper.AppendToMapping(...) on the shared static EntryHandler.Mapper/SearchBarHandler.Mapper. MAUI's AppendToMapping wraps the existing action in a new closure rather than replacing it — running this per-instance means every instantiation of BorderlessEntry (pervasive via ExtendedEntry, re-created on every CollectionView item-template recycle in passenger content views) or SearchView permanently adds another wrapping layer to the shared mapper for the life of the process, never unwound.
Impact
Unbounded compounding overhead (O(N) delegate chain) and closures held alive across the whole session — worsens continuously the longer the app runs.
Triggers
Every navigation to/from a form page (ExtendedEntry) or a search page (SearchView); every passenger row added.
Fix
Move AppendToMapping into a static constructor or a one-time MauiProgram handler-registration block.
Safe / minimal — high value

File

7. Memory

Native view + event-observer leak on iOS dropdowns

CriticalMemory
Files
Platforms/iOS/Handlers/IosDropDownBox.cs:26,105 (static Instances list) and :22-23,229-242 (keyboard NSNotificationCenter observers)
Why
Every IosDropDownBox (backing CustomDropdown, used in Signup/BusinessInformationView etc., often several per page) adds itself to a static list in its constructor and is never removed — CustomDropdownHandler.DisconnectHandler only cleans up its own event wiring. The two NSNotificationCenter keyboard observers registered per instance are likewise never removed.
Impact
Every dropdown ever created on iOS is pinned alive (native view tree + observers) for the entire app session, continuously handling keyboard events against detached views.
Fix
Remove this from Instances and dispose the two observers from a teardown path invoked by DisconnectHandler. The Android equivalent (CustomDropdownHandler.cs) already does this correctly — use as reference.
Safe / minimal — high value

See also §6 (Async/Multithreading) for the loading-indicator reference-counting leak and the dead Destory() cleanup-path leak — both are Memory-category findings cross-referenced there to keep the DI/lifecycle story together.

Confirmed correct

  • Of 41 += subscriptions found repo-wide, all except the iOS dropdown case are correctly paired with -= or are legitimate one-time app/window-lifetime subscriptions.
  • StepBarViewCell/StepBarComponentView/SegmentedControl all correctly unsubscribe before resubscribing on binding-context change.
  • WeakReferenceMessenger/MessagingCenter not used anywhere (N/A).
  • No Connectivity.ConnectivityChanged subscription exists anywhere (N/A).

Top 10 Highest-Impact Fixes

  1. Fix the loading-indicator lifecycle end-to-end (Android caching guard, iOS GIF re-decode, reference counting) — fires on ~15 call sites, i.e. essentially every API call in the app. Single biggest cumulative win.
  2. Move BorderlessEntry/SearchView's AppendToMapping calls to static constructors — stops an unbounded, session-long compounding cost touching nearly every form and recycled CollectionView item template.
  3. Fix IosDropDownBox's static Instances leak + orphaned keyboard observers — permanent native memory/view leak on iOS, one instance per dropdown ever shown.
  4. Add AllowConcurrentExecutions = false to LoadMoreAsync (×4) and ConfirmBooking — cheap, mechanical fix, eliminates duplicate API calls, duplicate rows, and a duplicate-booking risk.
  5. Fix IUpiPaymentCallbackService DI lifetime + wire up real cleanup — do both together, or the fix trades a functional bug for a leak.
  6. Cache the parsed auth token in AuthService instead of re-reading SecureStorage + re-parsing the JWT on every call — latency win on literally every API request.
  7. Add in-memory caching to LookupService — removes 6 redundant network round-trips from every Signup visit.
  8. Fix HotelsPage.xaml's CollectionView-in-ScrollView nesting — the one confirmed real virtualization anti-pattern over unbounded data.
  9. Wire AppJsonContext into Refit's RefitSettings — switches every API (de)serialization from reflection to source-gen, plus removes an AOT/trimming risk.
  10. Guard rapid picker/date-change handlers with cancellation (Dashboard/Flights/PaxCalendar) — eliminates the stale-response race after fast user interaction.
