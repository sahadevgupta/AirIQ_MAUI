Top Findings by Priority

Severity Issue Location (File:Line) Why It Matters Recommended Solution
Blocker Hardcoded API credentials Extensions/RefitClientServiceInitializer.cs:40-41 Exposes external service keys through source, logs, and extracted binaries. Move keys to secure configuration (environment/secret store), inject via options, rotate exposed keys.
Blocker Hardcoded login defaults ViewModels/LoginPageViewModel.cs:19,22 Creates unauthorized access risk and compliance violations in production builds. Replace defaults with empty values and guard test credentials behind debug-only compilation flags.
High Sensitive login logging ViewModels/LoginPageViewModel.cs:43-44,49 Username/password and user payload can leak through logs and diagnostics. Remove credential logging, redact sensitive fields, and log only non-PII identifiers.
High Unsafe null-forgiving auth/storage Services/SecureStorageService.cs:14,17; Services/ApiServiceBase.cs:60 Can cause runtime crashes and unpredictable auth behavior under null states. Replace null-forgiving with explicit null checks; return nullable/TryGet results and handle failures centrally.
High Unobserved async work ViewModels/FlightsPageViewModel.cs:60,72; ViewModels/DashboardPageViewModel.cs:60; ViewModels/FlightBookingPageViewModel.cs:266 Fire-and-forget tasks can fail silently, leaving stale UI and hidden bugs. Await async calls where possible; otherwise use a SafeFireAndForget helper that captures and logs exceptions.
Medium Async lifecycle initialization Views/SignupPage.xaml.cs:16,21 Timing delays and async-void patterns increase race conditions on startup. Move async initialization to lifecycle methods (OnAppearing/Loaded), remove fixed delay, return Task-based flows.
Medium Navigation without resilience Services/ShellNavigationService.cs:13-14,25-26; Services/NavigationService.cs:213,220 Unhandled route errors can break flows with no consistent fallback behavior. Wrap navigation APIs in try/catch, emit telemetry, and surface user-safe fallback messaging.
Low Artificial UI delay Platforms/Android/Handlers/CustomDropdownHandler.cs:209 One-second delay in dropdown population hurts responsiveness and UX quality. Remove Task.Delay; update adapter immediately or debounce based on actual user input events.

Execution Roadmap

Step 1: Security Hotfix (Immediate)

Remove hardcoded secrets and credentials. Mask and minimize auth-related logs.

Step 2: Async and Exception Safety

Replace service-level async void, add safe fire-and-forget wrapper, and harden null handling.

Step 3: Lifecycle and Navigation Reliability

Refactor async page initialization and add try/catch with telemetry in navigation boundaries.

Step 4: Quality Improvements

Remove artificial delays, simplify nullable state usage, and enforce analyzer rules in CI.
